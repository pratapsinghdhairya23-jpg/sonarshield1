# SONARSHIELD
### AI-Powered Underwater Debris & Anomaly Intelligence
Smart India Hackathon 2026 · Problem Statement SIH26057

SONARSHIELD is a working end-to-end prototype that takes a Side-Scan Sonar
(SSS) image, preprocesses it, detects and segments candidate objects,
computes a transparent risk/anomaly score, visualizes everything on a
maritime-intelligence-style dashboard and map, and generates a PDF
inspection report — all through a real FastAPI backend and a real React
frontend that talk to each other over HTTP.

---

## 1. What's real vs. what's a labeled fallback (read this first)

This is a hackathon **prototype**, built to be honest about what is and
isn't a trained AI model. Every one of these is surfaced in the UI with a
badge, never silently assumed:

| Component | What actually runs | How it's labeled |
|---|---|---|
| Preprocessing | Real OpenCV: denoise, CLAHE, normalize, unsharp-mask | (no fallback needed — this is genuine image processing) |
| Detection | A real, locally fine-tuned **YOLOv8-nano** model is tried first (see §4a). If unavailable or it finds nothing, bundled demo images fall back to fixed hand-authored annotations; any other image falls back to a deterministic classical-CV pipeline | `detector_mode: YOLO_TRAINED`, `DEMO_ANNOTATED`, or `HEURISTIC_CV` |
| Segmentation | A real U-Net (PyTorch) architecture is included and will be used automatically **if** you drop trained weights into `backend/ml/weights/unet_sonar.pt`. No weights ship with this repo (no training was run against the full AI4Shipwrecks dataset here), so by default it uses Otsu-threshold + morphology inside each detected box | `segmentation_mode: UNET_TRAINED` or `CV_FALLBACK` |
| IoU / Dice / Precision / Recall | Computed for real, against the bundled synthetic ground-truth masks | Always labeled `DEMO / SAMPLE METRICS` |
| Risk / Anomaly score | A transparent, hand-authored formula (see §5) | Always labeled `Prototype Risk Assessment — not scientifically validated` |
| Survey Map coordinates | Simulated, generated from image pixel position offset from a fixed base point | Badge: `SIMULATED SURVEY DATA` |
| Demo sonar images | Synthetically generated with code (seabed texture + acoustic-shadow object signatures) — **not real sonar data** | Badge: `SYNTHETIC DEMO DATA` |

The system-wide mode badge in the top bar shows **DEMO MODE** unless a real
`unet_sonar.pt` file is present, in which case it shows **AI MODEL MODE**.

## 4. Datasets

- **AI4Shipwrecks** (primary reference dataset) — side-scan sonar images with
  binary segmentation masks (0 = background, 1 = shipwreck/debris region).
  Get it at: https://deepblue.lib.umich.edu/data/concern/data_sets/8623hz41x
  (project page: https://umfieldrobotics.github.io/ai4shipwrecks/). This
  prototype does **not** claim AI4Shipwrecks contains multi-class debris
  labels — it's binary, and we use it that way.
- **SubPipe** — supporting sonar/detection data for pipeline/cable-like
  targets. We don't require downloading the full dataset; drop a few sample
  SSS images into `data/demo/` manually if you want to experiment with it.
  We do not claim it contains general underwater debris classes.
- **Bundled demo data** — 7 synthetic sonar-like PNGs generated by
  `backend/ml/demo_data_gen.py`, with matching binary masks and fixed
  annotations in `data/demo/annotations.json`. Regenerate anytime with:
  ```
  python backend/ml/demo_data_gen.py
  ```

### Using real AI4Shipwrecks images
Drop any `.png`/`.jpg`/`.tiff` sonar images into `data/demo/` (or just
upload them through the UI's **Upload Image** button — they don't need to
be in `data/demo/` at all). Images not found in `annotations.json` are
automatically routed through the trained YOLO detector first, then the
`HEURISTIC_CV` detector if YOLO finds nothing.

## 4a. YOLOv8 detector — what's actually trained here

A real YOLOv8-nano model **is included and does run real inference** —
this is not a stub. Concretely:

1. `backend/ml/build_yolo_dataset.py` converts the 7 bundled synthetic
   demo images + their fixed annotations into YOLO training format
   (5 images train / 2 held out for validation).
2. `backend/ml/train_yolo.py` fine-tunes a COCO-pretrained `yolov8n.pt`
   on that tiny dataset (single class: `sonar_anomaly`).
3. The resulting weights ship at `backend/ml/weights/yolo_sonar.pt` and
   are loaded automatically by `backend/ml/yolo_detector.py`.

**Honestly: this is a proof-of-concept, not a production detector.**
Trained on 7 synthetic images, it correctly localizes the object it was
shown on both training images and the 2 held-out validation images (real,
if imperfect, generalization — verified in this repo's dev history) and
correctly finds *nothing* on genuine random noise. But it has never seen
real sonar data, and its confidence calibration reflects the tiny dataset.
Retraining on real AI4Shipwrecks/SubPipe annotations (hundreds of labeled
frames minimum) is the way to make this production-grade:
```bash
python backend/ml/build_yolo_dataset.py   # or write your own equivalent for real data
python backend/ml/train_yolo.py --data your_data.yaml --epochs 100
```
Training run logs/metrics land in `backend/ml/yolo_runs/sonar_anomaly/`.

### Training a real U-Net
`backend/ml/segmentation.py` contains a full 4-level U-Net you can train
against AI4Shipwrecks masks with a standard PyTorch training loop (not
included, to keep this prototype runnable without a GPU/dataset). Save the
resulting weights to `backend/ml/weights/unet_sonar.pt` — the backend will
pick them up automatically on next restart and switch to `AI MODEL MODE`.

## 5. Risk / Anomaly scoring formula (transparent, prototype-only)

```
Risk Score = 40% × Detection Confidence
           + 20% × Object Area (normalized to image size)
           + 20% × Acoustic Shadow Evidence
           + 20% × Boundary / Shape Evidence (Canny edge density)

0–39   → LOW
40–69  → MEDIUM
70–100 → HIGH
```

This is implemented in `backend/ml/anomaly.py`. It is a hand-authored
heuristic for demonstration purposes — **not** a scientifically validated
maritime risk-assessment methodology.

## 6. Installation & running

### Prerequisites
- Python 3.10+
- Node.js 18+
- ~2 GB free disk (PyTorch CPU wheel)

### Backend
```bash
cd sonarshield
pip install -r backend/requirements.txt --break-system-packages   # or use a venv
python backend/ml/demo_data_gen.py      # generates data/demo/* (safe to re-run)
uvicorn backend.main:app --reload --port 8000
```
Backend runs at `http://127.0.0.1:8000` (Swagger docs at `/docs`).

> Note: `torch` is only required for the (optional) trained-U-Net inference
> path. If you don't plan to load real weights, you can remove it from
> `requirements.txt` and comment out the `import torch` lines in
> `backend/ml/segmentation.py` — the CV fallback path doesn't need it.

### Frontend
```bash
cd sonarshield/frontend
npm install
npm run dev
```
Frontend runs at `http://127.0.0.1:5173` and proxies `/api` and `/static`
to the backend automatically (see `vite.config.ts`).

### One-command local start (two terminals, or use `&`)
```bash
# terminal 1
uvicorn backend.main:app --reload --port 8000
# terminal 2
cd frontend && npm run dev
```

### Docker
```bash
docker-compose up --build
```
Frontend: `http://localhost:5173` · Backend: `http://localhost:8000`

## 7. Demo Mode

Demo Mode is automatic and needs zero setup:
1. Open the app → **LOAD DEMO** (or go to **Sonar Analysis** → **Load Demo Sonar**)
2. Pick one of the 7 synthetic sonar images
3. Click **Enhance**, then **Run AI Analysis**
4. Explore **AI Detection**, **Anomaly Intelligence**, **Survey Map**, **Reports**

Every demo result is deterministic and repeatable — the same demo image
always produces the same detection boxes and scores, which makes it safe
to demo live without surprises.

## 10. Troubleshooting

- **"Could not read image file"** — the uploaded file isn't a valid
  PNG/JPG/JPEG/TIFF, or is corrupted. Try a different file.
- **Backend unreachable from frontend** — confirm `uvicorn` is running on
  port 8000; the Vite dev proxy targets `http://127.0.0.1:8000`.
- **`torch` install fails / disk space** — see the note in §6; the CV
  fallback path works without torch installed at all if you strip the
  import.
- **Large bundle-size warning on `npm run build`** — cosmetic only (single
  JS chunk ~840 KB); doesn't affect functionality.

## 11. Limitations (please read before presenting)

- No trained neural **segmenter** ships with this prototype (U-Net
  architecture included, no pretrained weights) — falls back to
  classical, deterministic CV, clearly labeled as such. A real, locally
  fine-tuned **YOLOv8 detector** does ship (see §4a) but was trained on
  only 7 synthetic images — genuine inference, proof-of-concept accuracy.
- The heuristic-CV detection fallback (used when YOLO/demo-annotation
  paths don't apply) is contrast-based and will over-detect on genuinely
  random/non-sonar-like imagery — it assumes sonar-like structure.
- Risk scores are a demonstrative heuristic, not a certified maritime
  safety assessment.
- Map coordinates are simulated, not derived from real GPS/AUV telemetry.
- Demo sonar images are synthetic renders designed to resemble SSS output
  (bright return + acoustic shadow + nadir gap), not real acquired data.
- AI4Shipwrecks/SubPipe are referenced as **the datasets this prototype is
  designed to work with**, but are not bundled due to size/licensing —
  see §4 for how to plug them in.
